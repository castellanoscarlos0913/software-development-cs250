## Course Reflections & Essential Questions

### Interpreting User Needs and Implementing User Stories
Interpreting user needs requires looking beyond technical specifications to understand the actual business problem a user is trying to solve. Creating user stories helps bridge this gap by framing features from the end-user's perspective through the standard template: *"As a [type of user], I want [an action] so that [a benefit/value]."* This ensures that development remains centered on customer value rather than raw technical implementation. Breaking down user stories with clear acceptance criteria and a strict Definition of Done (DoD) establishes tangible expectations, prevents scope ambiguity, and ensures developers build exactly what the user requires.

### Approach to Program Development & Future Agile Practices
My approach to developing programs centers on an iterative, incremental design philosophy. Rather than attempting to build an entire software system in a single massive phase, I prioritize breaking projects down into manageable, testable components that deliver working software early and often. Moving forward into future academic and professional development work, I plan to incorporate continuous integration, test-driven validation, and regular backlog refinement into my routine. Embracing iterative sprint cycles allows me to adapt quickly to evolving project requirements, catch integration defects early, and maintain steady development velocity.

### Being a Good Team Member in Software Development
Being an effective team member in software development requires radical transparency, active collaboration, and psychological safety. It means actively participating in daily stand-ups to communicate progress and blockers openly, collaborating across functional roles such as development and QA, and taking collective ownership of the codebase. A good team member welcomes constructive feedback during sprint retrospectives, actively mentors peers, respects diverse perspectives, and prioritizes team success over individual output.
